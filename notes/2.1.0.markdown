### Security

* `as.xml.Elem` no longer processes DOCTYPE declarations or resolves external
  entities. Previously a server response could use an external entity to read
  local files into the parsed `Elem` or to make the client issue further
  requests (CWE-611, XXE). DOCTYPE declarations, external general and parameter
  entities, external DTD loading and XInclude are now disabled, and secure
  processing is enabled. Thanks to Adrian Korwel for the report.

Responses that rely on a DTD, including those that only declare internal
entities, now fail to parse with a `SAXParseException`. If you need DTD support,
build your own handler with an explicitly configured parser.

The DOCTYPE ban relies on a feature specific to Xerces, which includes the JDK's
built-in parser. If you configure a SAX provider that doesn't recognize that
feature, `as.xml.Elem` fails outright rather than parse unprotected responses;
skipping external DTDs remains best-effort. Disabling external entities and
enabling secure processing don't rely on Xerces-specific features.
